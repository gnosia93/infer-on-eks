# 디퓨전 모델 평가와 선정 

## 1. 평가 방법

이미지 모델도 promptfoo처럼 "모델 × 프롬프트" 행렬로 비교할 수 있다. LLM 평가와 다른 점은 두 가지다. 비교할 정답 문자열이 없어서 채점을 점수 모델, VLM 판정, 사람 비교로 해야 한다. 그리고 이미지 생성이 GPU를 많이 쓰기 때문에 **생성과 채점을 나눠서**, 이미지는 한 번만 만들어 저장해 두고 채점만 여러 번 돌린다.

### 평가 순서

1. **테스트셋 만들기**: 가장 중요한 단계다. 지금 쓰는 상용 API 로그에서 실제 프롬프트를 카테고리별로 뽑는다. img2img는 입력 이미지와 지시문을 함께 뽑는다. **상용 모델이 만든 결과도 기준선으로 같이 저장**한다. 결국 판단할 질문은 "우리 프롬프트에서 오픈 모델이 상용 모델만큼 나오는가"이기 때문이다. 공개 벤치마크(예: 편집용 [GEditBench v2](https://arxiv.org/abs/2603.28547), 실제 사용자 요청 1,200개, 23개 과제)는 빠진 유형을 채우는 용도로 쓴다.
2. **생성**: 모델마다 권장 설정(스텝 수, guidance)을 따로 쓴다. 모든 모델에 같은 설정을 강제하면 공정하지 않다. 같은 시드라도 모델이 다르면 같은 그림이 나오지 않으므로 프롬프트당 시드를 여러 개 써서 평균으로 비교한다. 생성할 때 latency와 VRAM도 함께 기록한다.
3. **자동 채점**: 아래 표에 정리했다.
4. **사람 평가**: 일부 샘플(예: 100~200개)을 블라인드 A/B로 비교해 상용 기준선 대비 승률을 본다. 이 결과로 어떤 자동 지표가 우리 팀의 판단과 맞는지도 확인한다.
5. **운영 지표와 라이선스**: 아래 "최종 선택 기준"에 정리했다.

### 채점 지표

| 볼 것 | text-to-image | img2img / 편집 |
|---|---|---|
| 프롬프트·지시문을 따랐는가 | VQAScore ([t2v_metrics](https://github.com/linzhiqiu/t2v_metrics)) | VLM 판정 ([VIEScore](https://www.emergentmind.com/topics/viescore) 방식) |
| 사람이 보기에 좋은가 | HPS, ImageReward, PickScore 같은 선호 점수 모델 | 같음 |
| 원본을 지켰는가 | 해당 없음 | 원본과의 지각 유사도(DreamSim, LPIPS), 일관성 판정 모델(GEditBench v2의 PVC-Judge) |
| 상용 모델보다 나은가 | VLM pairwise 판정, 사람 블라인드 A/B 승률 | 같음 |

지표를 고를 때 참고할 점:

- [GenAI-Bench 논문](https://arxiv.org/html/2406.13743)에서는 VQAScore로 고른 이미지가 PickScore, HPSv2, ImageReward로 고른 이미지보다 사람 평가를 2~3배 더 많이 올렸다. 여러 조건이 섞인 복합 프롬프트에서 차이가 특히 컸다.
- 반면 [2025년 지표 비교 연구](https://arxiv.org/html/2509.21227)는 과제 유형마다 잘 맞는 지표가 달라서, 어느 지표도 모든 경우에 가장 좋지는 않다고 결론 냈다. 지표 하나만 믿지 말고 사람 평가로 보정한다.
- 편집에서 원본 유사도만 보면 아무것도 바꾸지 않은 결과가 만점을 받는다. 지시문 이행 점수와 반드시 같이 본다.
- FID는 수천 장 단위로 분포를 비교하는 지표라 수백 개 프롬프트로 모델을 고를 때는 잘 맞지 않는다.

### YAML로 돌리는 최소 구성

**eval_t2i.yaml**: 편집 평가는 프롬프트에 `"image"`를 넣고, 편집을 지원하는 모델만 넣은 config를 따로 만든다.

```yaml
output_dir: runs/t2i
prompts: prompts_t2i.jsonl      # {"id": "p001", "category": "product", "prompt": "..."}
seeds: [0, 1, 2, 3]
resolution: [1024, 1024]
models:                          # 모델마다 권장 설정을 따로 둔다
  - name: candidate-a
    repo: <huggingface-repo-id>
    call: {num_inference_steps: 28, guidance_scale: 3.5}
  - name: candidate-b
    repo: <huggingface-repo-id>
    call: {num_inference_steps: 8, guidance_scale: 1.0}
```

**generate.py**: 모델을 한 번씩만 올려서 이미지를 만들고 `manifest.jsonl`에 기록한다. 다시 실행하면 이미 만든 이미지는 건너뛴다.

```python
import json
import sys
import time
from pathlib import Path

import torch
import yaml
from diffusers import DiffusionPipeline
from diffusers.utils import load_image

cfg = yaml.safe_load(Path(sys.argv[1]).read_text())
prompts = [json.loads(l) for l in Path(cfg["prompts"]).read_text().splitlines() if l.strip()]
out_dir = Path(cfg["output_dir"])
out_dir.mkdir(parents=True, exist_ok=True)
width, height = cfg.get("resolution", [1024, 1024])

with (out_dir / "manifest.jsonl").open("a") as manifest:
    for m in cfg["models"]:
        dtype = getattr(torch, m.get("dtype", "bfloat16"))
        pipe = DiffusionPipeline.from_pretrained(m["repo"], torch_dtype=dtype).to("cuda")
        for p in prompts:
            for seed in cfg["seeds"]:
                path = out_dir / m["name"] / f'{p["id"]}_s{seed}.png'
                if path.exists():
                    continue
                kwargs = {
                    "prompt": p["prompt"],
                    "generator": torch.Generator("cuda").manual_seed(seed),
                    **m.get("call", {}),
                }
                if "image" in p:
                    kwargs["image"] = load_image(p["image"])
                else:
                    kwargs.update(width=width, height=height)

                torch.cuda.reset_peak_memory_stats()
                torch.cuda.synchronize()
                start = time.perf_counter()
                image = pipe(**kwargs).images[0]
                torch.cuda.synchronize()
                latency = time.perf_counter() - start

                path.parent.mkdir(parents=True, exist_ok=True)
                image.save(path)
                manifest.write(json.dumps({
                    "model": m["name"], "prompt_id": p["id"], "category": p.get("category"),
                    "seed": seed, "path": str(path), "latency_s": round(latency, 2),
                    "peak_vram_gb": round(torch.cuda.max_memory_allocated() / 2**30, 1),
                }) + "\n")
        del pipe
        torch.cuda.empty_cache()
```

**score.py**: 저장된 이미지를 VQAScore로 채점하고 모델별로 요약한다.

```python
import pandas as pd
import t2v_metrics

rows = pd.read_json("runs/t2i/manifest.jsonl", lines=True)
prompts = pd.read_json("prompts_t2i.jsonl", lines=True).set_index("id")["prompt"]

vqa = t2v_metrics.VQAScore(model="clip-flant5-xxl")  # 지원 모델은 t2v_metrics README 참고
rows["vqascore"] = [float(vqa(images=[r.path], texts=[prompts[r.prompt_id]])) for r in rows.itertuples()]

summary = rows.groupby("model").agg(
    vqascore=("vqascore", "mean"),
    latency_p50=("latency_s", "median"),
    latency_p95=("latency_s", lambda s: s.quantile(0.95)),
    peak_vram_gb=("peak_vram_gb", "max"),
)
print(summary.sort_values("vqascore", ascending=False))
print(rows.groupby(["category", "model"])["vqascore"].mean().unstack())  # 카테고리별 비교
rows.to_csv("runs/t2i/scores.csv", index=False)
```

모델에 따라 전용 파이프라인 클래스나 추가 설정이 필요할 수 있다. 이 코드는 GPU 환경에서 직접 실행해 보지 않았다. 각 모델의 첫 장은 워밍업 시간이 섞이므로 latency 집계에서 뺀다.

### promptfoo 활용

Google Cloud의 [예제](https://googlecloudplatform.github.io/applied-ai-engineering-samples/genai-on-vertex-ai/gemini/model_upgrades/image_prompt_alignment/promptfoo/)가 이 방식으로 Imagen 2와 Imagen 3를 비교한다. 이미지를 미리 만들어 두고, 프롬프트와 이미지 경로를 `dataset.jsonl`에 넣는다. 그다음 promptfoo에서 VLM 판정 모델이 "프롬프트 중 이미지에 빠진 요소"를 찾게 하고, Python으로 만든 지표로 점수를 낸다. 위 `manifest.jsonl`을 이 형식으로 바꾸면 채점과 결과 비교 화면(`promptfoo view`)은 기존 promptfoo로 할 수 있다. VQAScore 같은 점수는 [Python assertion](https://www.promptfoo.dev/docs/configuration/expected-outputs/python)으로 붙인다.

### 최종 선택 기준

- **운영 지표**: 목표 GPU와 해상도에서 장당 latency(p50/p95), 최대 VRAM, 배치 처리량, 장당 비용을 비교한다. 품질 점수와 latency를 한 그래프에 놓으면, 스텝 수가 적은 경량 모델과 큰 모델 중 무엇을 고를지 판단하기 쉽다.
- **라이선스**: 오픈 웨이트 모델이라도 비상업 용도로만 쓸 수 있거나 회사 매출 규모로 사용을 제한하는 경우가 있다. 상용 서비스에 넣기 전에 반드시 확인한다.

### 고를 때 참고할 점

- 리더보드의 95% 신뢰구간이 ±10~16점이라, 이 범위 안의 점수 차이는 사실상 같은 수준이다.
- 한국에서 서비스한다면 H3-Image와 HunyuanImage는 지역 제외 조항 때문에 그대로 쓸 수 없다.
- 라이선스를 해석할 때는 회사 법무 검토를 받아야 한다.

### 자체 평가에 넣을 후보

- **T2I**: HiDream-O1-Image, Ming-Image-0.1-Design(디자인·글자 위주인 경우), Z-Image Turbo(속도·비용 기준선), Cosmos3-Super-Text2Image
- **편집**: Qwen-Image-Edit-2511, HiDream-O1-Image, FLUX.2 [klein] 4B
- **라이선스 예산이 있다면**: FLUX 3 Image Klein, Ideogram 4, Fibo 2.0도 비교 대상이다. 상업 이용 가능한 최상위 모델과의 점수 차이가 T2I는 25~40점으로 작고, 편집은 70~90점으로 크다. 그래서 편집 품질이 중요하다면 라이선스를 사는 쪽이 나을 수 있다.

리더보드는 일반적인 프롬프트로 매긴 순위다. 위 후보를 1장의 평가 방식으로 실제 서비스 프롬프트에 돌려 보고 최종 결정한다.
