# S3 / AWS DataSync를 활용한 모델 가중치 빠른 로딩 기법

대규모 AI 모델 가중치(Model Weights)를 S3와 AWS DataSync를 조합해 빠르게 로딩하려면, **DataSync로 스토리지 계층을 미리 동기화(Pre-staging)하고, S3는 고성능 병렬 스트리밍 및 전용 프로토콜을 결합하는 아키텍처**를 구성해야 합니다.

---

## 1. 전체 아키텍처 전략: 계층 분리 및 역할을 명확히 하기
S3는 대용량 객체 저장에 최적화된 반면, 온프레미스 환경이나 특정 공유 파일 시스템과의 대량 데이터 이동에는 한계가 있습니다. 따라서 다음과 같이 역할을 나눕니다.
* **AWS DataSync:** 온프레미스 스토리지(NAS, NFS/SMB)에서 AWS(S3 또는 FSx for Lustre)로 초기 가중치 파일 및 주기적 체크포인트를 고속으로 동기화할 때 사용합니다.
* **S3 + 고속 로딩 클라이언트:** 클라우드 내 GPU 인스턴스(EC2, EKS 등)로 가중치를 최종 적재할 때 사용합니다.

---

## 2. AWS DataSync를 활용한 고속 데이터 스테이징 (Pre-staging)
학습이나 추론 인스턴스가 뜨기 전, 데이터를 가장 가까운 스토리지로 빠르게 옮겨놓는 단계입니다.

* **S3 → Amazon FSx for Lustre 연동 (가장 빠른 추론/학습 로딩):**
  * 모델 가중치가 수십~수백 GB 이상이고 여러 GPU 노드가 동시에 읽어야 한다면, S3에서 직접 읽는 것보다 **DataSync 또는 S3 DRA(Data Repository Association)**를 통해 초고속 병렬 파일 시스템인 **FSx for Lustre**로 데이터를 미리 내려받는 것이 훨씬 빠릅니다.
  * Lustre는 초당 수백 GB의 처리량과 서브 밀리초(sub-millisecond) 지연 시간을 제공하여, 모델 로딩 병목을 사실상 제거합니다.
* **DataSync 전송 최적화 설정:**
  * **대역폭 제한 해제 및 병렬 처리:** DataSync 태스크 생성 시 네트워크 대역폭 제한을 최대로 풀고, 파일 단위가 크다면 멀티파트 전송을 적극 활용합니다.
  * **증분 전송(Incremental Transfer):** 모델 파인튜닝 후 변경된 레이어나 체크포인트만 전송할 때 DataSync의 메타데이터 비교 기능을 활용하면 전체 재전송 시간을 크게 줄일 수 있습니다.

---

## 3. S3에서 GPU 메모리로의 초고속 직접 로딩 기법
DataSync를 통해 S3에 최신 가중치가 올라왔다면, 추론/학습 컨테이너가 S3에서 데이터를 당겨올 때 다음 기법들을 적용해야 합니다.

| 기법 / 도구 | 핵심 원리 | 기대 효과 및 특징 |
| :--- | :--- | :--- |
| **S3 Express One Zone** | 단일 가용 영역(AZ) 내 고성능 디렉토리 버킷 사용 | 일반 S3 표준 대비 **최대 10배 빠른 데이터 액세스 속도** 및 일관된 한 자릿수 밀리초 지연 시간 제공 (GPU 인스턴스와 동일 AZ 배치 필수). |
| **Mountpoint for Amazon S3** | S3 버킷을 로컬 파일 시스템처럼 마운트 (Rust 기반) | 고처리량 순차/병렬 읽기에 최적화되어 있어, 일반 `s3fs` 대비 압도적인 속도로 대용량 가중치 파일을 읽어 들임. |
| **s5cmd 활용** | Go 언어 기반의 초고속 병렬 S3 CLI 도구 | 기본 AWS CLI(`aws s3 cp`)보다 **최대 10~30배 빠른 다운로드 속도** 제공. 컨테이너 시작 스크립트(Init Container)에서 NVMe 인스턴스 스토어로 복사할 때 필수적. |
| **Run:ai Model Streamer / Safetensors** | S3에서 디스크를 거치지 않고 GPU VRAM으로 직접 스트리밍 | 로컬 디스크 I/O 병목을 건너뛰고 네트워크 대역폭을 100% 활용해 VRAM에 직접 적재. `Safetensors` 포맷과 결합 시 역직렬화 오버헤드 최소화. |

---

## 4. 실전 최적화 체크리스트
1. **인스턴스 스토어(NVMe SSD) 활용:** EBS 볼륨 대신 `p4d`, `p5`, `g5`, `g6` 등 GPU 인스턴스에 기본 장착된 **로컬 NVMe SSD**에 `s5cmd`로 가중치를 먼저 병렬 다운로드한 뒤 메모리에 올리세요.
2. **파일 청크(Chunk) 크기 조정:** 100GB짜리 단일 파일 하나보다 **2GB~5GB 단위로 분할(Sharding)된 Safetensors 파일** 여러 개를 동시에 병렬(Multi-threaded)로 다운로드하는 것이 S3의 다중 커넥션 처리량을 극대화하는 데 유리합니다.
3. **VPC 엔드포인트(Gateway Endpoint) 필수 구성:** S3와 EC2/EKS 간 트래픽이 NAT 게이트웨이를 타지 않고 AWS 내부 백본망을 통해 최대 대역폭(최대 100Gbps 이상)으로 통신하도록 S3 Gateway Endpoint를 반드시 연결하세요.
